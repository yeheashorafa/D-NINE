# D-NINE CMS Content Inventory

| واجهة الموقع | مصدر التحرير | نوع المحتوى | التحديث |
|---|---|---|---|
| الهيرو والفيديو ولماذا دي ناين والمنهجية وFAQ | `homePage` | عربي/إنجليزي + صور/فيديو | Webhook + revalidation |
| القطاعان والمجموعات والخدمات والباقات | `sectorPage` | وثيقتان مرتبتان | Webhook + tag `sectors` |
| المشاريع ومعرض الوسائط | `project` | وثائق متعددة | Webhook + المشروع/الأعمال |
| تصنيفات الأعمال الأربعة | `contentCategory` | أربع وثائق ثابتة | Webhook؛ لا تُضاف قيم حرة |
| الشركاء والشعارات | `partner` | وثائق متعددة مرتبة | Webhook + `partners` |
| آراء العملاء | `testimonial` | وثائق متعددة مرتبة/نشطة | Webhook + `testimonials` |
| المدونة والكتّاب | `blogPost`, `author` | وثائق متعددة | Webhook + المقال/المدونة |
| من نحن والخدمات والأعمال والمدونة والتواصل | Singletons | عربي/إنجليزي + SEO | Webhook لكل صفحة |
| الخصوصية والشروط | `privacyPage`, `termsPage` | Portable Text ثنائي اللغة | Webhook لكل صفحة |
| الشعار والقائمة والفوتر والتواصل والسوشيال وSEO | `siteSettings` | إعدادات عامة | Webhook لجميع الصفحات |
| ألوان الوضعين | `themeSettings` | لوحات ألوان | Webhook لجميع الصفحات |
| رسائل التواصل والحجز والنشرة | Supabase/Prisma | جداول تشغيلية | فوري عند الإرسال |

## عناصر تقنية لا يحررها العميل

- المسارات، حماية CSP/CORS، rate limiting، validation، webhook signatures وبنية قاعدة البيانات.
- fallback النصي/التصميمي يستخدم فقط عند غياب محتوى Sanity، ولا يحتوي أسماء عملاء أو آراء غير موثقة.
- مفاتيح Sanity وSMTP وقاعدة البيانات محفوظة في متغيرات البيئة وليست حقول CMS.

## الأنواع الملغاة

- `teamMember` وقسم الفريق.
- `service` و`serviceOffering` القديمان؛ البديل الوحيد هو `sectorPage` الهرمي.
- التصنيفات الحرة والقديمة للمشاريع؛ المصدر المعتمد أربعة تصنيفات فقط.

## الرسائل الواردة

بيانات النماذج لا تُنسخ إلى Sanity لتجنب تخزين بيانات شخصية في نظامين. يظهر في Studio رابط مباشر إلى
جدول Supabase المحمي عبر `SANITY_STUDIO_SUPABASE_INBOX_URL`. الحالة التشغيلية موجودة في عمود `status`.
